ITALIANO
--------------------------------------------------------------------

Tre passaggi. Il primo e' il piu' importante: evita gli avvisi di
sicurezza di Windows su tutte le postazioni.

I pacchetti sono due e fanno la stessa cosa:

  Inventario-windows-senza-exe.zip   CONSIGLIATO. Dentro c'e' il Python
      ufficiale di python.org, firmato dalla Python Software Foundation,
      e il programma in chiaro come file .py. Nessun eseguibile
      costruito da noi, quindi niente di non firmato da far passare.

  Inventario-windows.zip             contiene Inventario.exe, il
      programma in un eseguibile unico. Piu' comodo, ma e' un file non
      firmato che nasce nuovo a ogni versione: e' quello che gli
      antivirus guardano con sospetto.

Le istruzioni qui sotto valgono per tutti e due: dove leggi
Inventario.exe, con il pacchetto consigliato leggi Inventario.py.


1) SBLOCCA IL FILE ZIP, PRIMA DI ESTRARLO

   Tasto destro sul file Inventario-windows.zip  >  Proprieta'
   In fondo alla scheda Generale, spunta  [x] Annulla blocco
   Applica  >  OK

   Windows marca come "scaricato da Internet" tutto cio' che estrai
   da un archivio bloccato. Sbloccando lo zip PRIMA di estrarlo, il
   marchio non passa ai file, e il programma parte senza avvisi.

   Se hai gia' estratto senza sbloccare: cancella la cartella
   estratta, sblocca lo zip e riestrai.

   Se la casella "Annulla blocco" NON c'e', va benissimo: vuol dire
   che Windows non ha marchiato il file e non c'e' niente da
   sbloccare. Vai avanti al passaggio 2.


2) ESTRAI LA CARTELLA SULLA CARTELLA DI RETE CONDIVISA

   Estrai tutto il contenuto dello zip in una cartella della share,
   per esempio:   \\server\Condivisa\Inventario\

   Con il pacchetto consigliato dentro trovi Inventario.py, la
   cartella inventario e la cartella python, insieme alle cartelle di
   lavoro (Produzione, Backup, Collaudo). Con l'altro pacchetto trovi
   Inventario.exe e _internal al loro posto. In nessuno dei due casi
   spostare o rinominare le sottocartelle: il programma non partirebbe
   piu'.

   Servono i permessi NTFS:
     - sul programma:    Lettura ed esecuzione
     - sulla cartella:   Modifica


3) CREA IL COLLEGAMENTO SUL DESKTOP DI OGNI POSTAZIONE

   Doppio clic su "Crea collegamento sul desktop.bat": riconosce da
   solo quale dei due pacchetti hai estratto, mette il collegamento sul
   desktop e ne lascia una copia nella cartella, da trascinare sul
   desktop degli altri.

   Con il pacchetto Inventario.exe va bene anche tasto destro
   sull'eseguibile > Mostra altre opzioni > Invia a > Desktop (crea
   collegamento).


AGGIORNARE IL PROGRAMMA PIU' AVANTI

   Sostituisci il contenuto della cartella con quello del pacchetto
   nuovo. Se prima c'era Inventario.exe e adesso usi il pacchetto
   senza eseguibile, CANCELLA Inventario.exe e la cartella _internal:
   altrimenti restano li' e chi li apre usa la versione vecchia del
   programma. Poi rifai i collegamenti sui desktop.

   La versione in uso e' scritta nella barra del titolo della
   finestra: e' il modo per accorgersene. I dati non si toccano: stanno in Produzione, e Backup e
   Collaudo restano dove sono.

   Se un file non si lascia cancellare, guarda PRIMA la sola lettura:
   tasto destro > Proprieta' > in fondo alla scheda Generale, togli la
   spunta da [x] Sola lettura. E' la causa piu' banale e anche la piu'
   frequente.

   Se non era quello, e' perche' qualcuno lo sta usando: Windows blocca
   l'eseguibile finche' un processo avviato da li' e' in esecuzione,
   anche da un altro computer.
   Sul server: Gestione computer > Cartelle condivise > File aperti,
   cerca "Inventario", vedi chi lo tiene aperto e chiudilo da li'.
   Poi riprova.


SE COMPARE ANCORA UN AVVISO

   "Windows ha protetto il PC"  ->  Ulteriori informazioni  >
   Esegui comunque. Succede la prima volta se lo zip non era stato
   sbloccato.

   "L'autore non e' verificabile"  ->  aggiungi il server ai siti
   Intranet locale: Opzioni Internet > Sicurezza > Intranet locale >
   Siti > Avanzate > aggiungi  \\server

   In alcune aziende l'esecuzione da share e' vietata da criteri di
   sicurezza (AppLocker): in quel caso serve un'eccezione dagli
   amministratori. Non e' un problema del programma.

ENGLISH
--------------------------------------------------------------------

Three steps. The first one matters most: it prevents Windows security
warnings on every workstation.

There are two packages and they do the same thing:

  Inventario-windows-senza-exe.zip   RECOMMENDED. Inside are the
      official python.org Python, signed by the Python Software
      Foundation, and the program in plain sight as .py files. No
      executable built by us, so nothing unsigned to get past security.

  Inventario-windows.zip             holds Inventario.exe, the program
      packed into a single executable. Handier, but it is an unsigned
      file born anew with every version: that is what antivirus
      software looks at with suspicion.

The instructions below apply to both: where you read Inventario.exe,
with the recommended package read Inventario.py.


1) UNBLOCK THE ZIP FILE, BEFORE EXTRACTING IT

   Right-click Inventario-windows.zip  >  Properties
   At the bottom of the General tab, tick  [x] Unblock
   Apply  >  OK

   Windows marks everything extracted from a blocked archive as
   "downloaded from the Internet". Unblocking the zip BEFORE
   extracting stops that mark reaching the files, and the program
   starts with no warnings.

   If you already extracted without unblocking: delete the extracted
   folder, unblock the zip and extract again.

   If the "Unblock" box is NOT there, that is fine: it means Windows
   did not mark the file and there is nothing to unblock. Go on to
   step 2.


2) EXTRACT THE FOLDER ONTO THE SHARED NETWORK FOLDER

   Extract the whole contents of the zip into a folder on the share,
   for example:   \\server\Shared\Inventory\

   With the recommended package you find Inventario.py, the inventario
   folder and the python folder, together with the working folders
   (Produzione, Backup, Collaudo). With the other package you find
   Inventario.exe and _internal in their place. In neither case move or
   rename the subfolders: the program would no longer start.

   NTFS permissions needed:
     - on the program:     Read and execute
     - on the folder:      Modify


3) CREATE THE DESKTOP SHORTCUT ON EVERY WORKSTATION

   Double-click "Crea collegamento sul desktop.bat": it works out by
   itself which of the two packages you extracted, puts the shortcut on
   the desktop and leaves a copy in the folder, to drag onto the
   others' desktops.

   With the Inventario.exe package you can also right-click the
   executable > Show more options > Send to > Desktop (create
   shortcut).


UPDATING THE PROGRAM LATER

   Replace the contents of the folder with those of the new package.
   If Inventario.exe was there before and you now use the package
   without an executable, DELETE Inventario.exe and the _internal
   folder: otherwise they stay and whoever opens them runs the old
   version of the program. Then redo the desktop shortcuts.

   The version in use is written in the window title bar: that is how
   you notice.
   The data is untouched: it lives in Produzione, and Backup and
   Collaudo stay where they are.

   If a file will not delete, check the read-only attribute FIRST:
   right-click > Properties > at the bottom of the General tab, clear
   the [x] Read-only box. It is the most banal cause and also the most
   common.

   If that was not it, it is because somebody is using it: Windows
   locks the executable while a process started from it is running,
   even from another computer.
   On the server: Computer Management > Shared Folders > Open Files,
   look for "Inventario", see who is holding it and close it there.
   Then try again.


IF A WARNING STILL APPEARS

   "Windows protected your PC"  ->  More info > Run anyway. This
   happens the first time if the zip had not been unblocked.

   "The publisher could not be verified"  ->  add the server to the
   Local intranet sites: Internet Options > Security > Local
   intranet > Sites > Advanced > add  \\server

   In some companies running from a share is forbidden by security
   policy (AppLocker): that needs an exception from the
   administrators. It is not a problem with the program.
